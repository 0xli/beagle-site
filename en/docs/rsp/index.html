RSP: signed rendezvous for calls

RSP sets up a call when your friend cannot be reached over Carrier: both sides prove their keys to a small node, which passes the call signaling between them. Paused: the node is switched off until a defect that ends calls at 60 seconds is fixed.

November 2026

What it is

RSP is paused

The RSP node has been switched off since 22 November 2026, 03:43 UTC, until the 60-second defect is fixed. There is no date for its return. While it is paused, RSP is inactive in every app: iOS and Android fall back to a push and a socket.io room, and the web app to Carrier. These fallbacks were read in each app's source and tested only for the web app's call bridge.

RSP (Rendezvous Signaling Protocol, rsp/1) is a signed meeting point for starting a call with a friend who is not online over Carrier. It carries call setup only. Audio and video stay on WebRTC.

  • Both sides prove their keys. The node checks a proof made with each identity key. There are no accounts.
  • One caller, one callee. Joining takes a one-time capability, and the first device to answer wins.
  • A listening app rings without a push. It can keep a connection to the node and get invitations directly.
  • Presence stays private. An app rings only for a friend. To anyone else, silence looks the same as being offline.
What the node can see

The node keeps call state in memory only, with no user records. It does see both userids, the timing, and the signaling it relays. JSON signaling is not end-to-end encrypted, and it can include IP addresses in connection candidates.

The order of a call

OrderPathWhen
1CarrierAlways first. If the friend answers there, nothing else is used.
2RSPCarrier did not reach the friend, and the friend advertises RSP. The caller creates the call and waits about 2 seconds for a ring, then sends a sealed wake push.
3socket.io roomThe friend does not advertise RSP, the node cannot create the call, or the wake is confirmed undelivered.

RSP is an extra path beside socket.io rooms and does not replace them. This is the protocol's order. Each app's current support is listed under Which apps have it. While the node is paused, step 2 fails and the apps fall back.

How a friend advertises it

The callee picks the node. It puts an rsp key in the extra field of its Carrier profile, which reaches friends and stays readable while it is offline. The host in this example is a placeholder:

{"rsp":{"protocol":"rsp/1","nodeUrl":"https://rsp.example.com"}}
  • The flag holds an address only: no presence, IP address or push token. nodeUrl must be HTTPS.
  • Merge the key into the existing extra, and remove it when RSP is switched off.
  • Decide from this flag, not from a friend's app version.

Low-level protocol client

Not a package for app developers

These two packages are for someone implementing RSP in their own stack. Beagle apps, beagle-ui and beagle-embed should not install or depend on them: they are protocol pieces, without friend policy, sealed push or media. A shared RSP layer in @decentnetwork/peer-webrtc is planned. It is not built or published, so there is no supported package for adding RSP to an app yet.

The sample cannot run against rio.beagle.chat now

That node is paused. The sample needs an RSP/1 node that you run, given in RSP_NODE_URL. The reference node's code is not public, so without a node of your own there is nothing to run it against at the moment.

For protocol implementers: two packages on npm, version 0.2.0, for Node 18 or later: rendezvous-protocol has the wire format and validators, and rendezvous-client has the client. Install the same version of both.

# Protocol implementers only. Not a dependency for Beagle apps.
mkdir rsp-demo && cd rsp-demo
npm init -y
npm install @decentnetwork/rendezvous-client@0.2.0 @decentnetwork/rendezvous-protocol@0.2.0 @decentnetwork/peer

Low-level protocol sample, not application code. Save it as call.mjs. It makes two throwaway identities in one process: one listens, and the other calls it through your node. The run command assumes a node on port 3100 of your own machine.

// Low-level RSP/1 sample for protocol implementers. Not application code.
// Two throwaway identities in one process, over an RSP/1 node that you run.
import { generateKeyPairSync, randomUUID } from "node:crypto";
import { RendezvousClient, carrierSigner, routeCall } from "@decentnetwork/rendezvous-client";
import { base58ToBytes, bytesToBase58, createCarrierRendezvousAuthProof } from "@decentnetwork/peer";

const NODE = process.env.RSP_NODE_URL;
if (!NODE) throw new Error("set RSP_NODE_URL to an RSP/1 node that you run");

function identity() {
  const jwk = generateKeyPairSync("x25519").privateKey.export({ format: "jwk" });
  const secret = new Uint8Array(Buffer.from(jwk.d, "base64url"));
  const userid = bytesToBase58(new Uint8Array(Buffer.from(jwk.x, "base64url")));
  const signer = carrierSigner({ userid, createProof: ({ serverPublicKey, transcript }) =>
    createCarrierRendezvousAuthProof(secret, base58ToBytes(serverPublicKey), transcript) });
  return { id: { method: "carrier-x25519", id: userid }, signer };
}

// A friend's `extra` is not the shape routeCall takes: convert it.
function advertisement(extra) {
  const rsp = JSON.parse(extra || "{}").rsp;
  if (rsp?.protocol === "rsp/1" && rsp.nodeUrl === NODE) return { rsp: true, nodeUrl: NODE };
}

const alice = identity();
const bob = identity();

// Bob listens, and rings only for a friend.
const listener = new RendezvousClient(NODE, bob.signer);
let invite;
listener.on("call:invite", async (i) => {
  if (i.caller.id !== alice.id.id) return; // not a friend: stay silent
  invite = { callId: i.callId, peer: i.caller, callExpiresAt: i.expiresAt, capability: i.joinCapability };
  await listener.ringing(invite);
});
await listener.listen();

// Alice calls. Carrier first, then RSP, then socket.io.
const bobExtra = JSON.stringify({ rsp: { protocol: "rsp/1", nodeUrl: NODE } });
const call = await routeCall({
  tryCarrier: async () => false, // pretend Bob is not reachable over Carrier
  advertisement: advertisement(bobExtra),
  signer: alice.signer,
  callId: randomUUID(),
  peer: bob.id,
  push: async () => { throw new Error("nobody rang: send a sealed wake push here"); },
  socketFallback: async () => ({ path: "socket.io" }),
});
console.log("path:", call.path);

// Bob answers. WebRTC offer and answer would follow on the same clients.
if (call.client) {
  const accepted = new Promise((resolve) => call.client.on("signal", resolve));
  await listener.join(invite);
  await listener.sendSignal({
    version: 1, callId: invite.callId, type: "call.accept", sequence: 1,
    timestamp: Date.now(), expiresAt: invite.callExpiresAt, encoding: "json", payload: "{}",
  });
  console.log("received:", (await accepted).type);
  call.client.close();
}
listener.close();
RSP_NODE_URL=http://127.0.0.1:3100 node call.mjs
# path: rsp-listen
# received: call.accept
Two details to get right

routeCall takes { rsp: true, nodeUrl }. If you pass a friend's extra as it is, it silently chooses socket.io. It also gives push the join capability in clear text: seal it to the callee before it goes into a push, and never log it.

The node: paused

https://rio.beagle.chat is paused until the 60-second defect is fixed, with no date for its return. It is the test-setup node, not a general node for every Beagle user, and the only one the apps are configured for.

The defect behind the pause

The node ends every call record 60 seconds after it was created, answered or not. The released web, iOS and Android apps also hang up an RSP call at that point, so fixing the node alone is not enough.
