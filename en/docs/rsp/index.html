RSP: signed rendezvous for calls

RSP sets up a call when your friend cannot be reached over Carrier: both sides prove their keys to a small node, which passes the call signaling between them. RSP/2 has run on rio.beagle.chat since 22 November 2026, and is in some of the apps.

November 2026

What it is

RSP (Rendezvous Signaling Protocol) is a signed meeting point for starting a call with a friend who is not online over Carrier. It carries call setup only. Audio and video stay on WebRTC. The current version is RSP/2.

  • Both sides prove their keys. The node checks a proof made with each identity key. There are no accounts.
  • One caller, one callee. Joining takes a one-time capability, and the first device to answer wins.
  • A listening app rings without a push. It can keep a connection to the node and get invitations directly.
  • Presence stays private. An app rings only for a friend. To anyone else, silence looks the same as being offline.
What the node can see

The node keeps call state in memory only, with no user records. It does see both userids, the timing, and the signaling it relays. JSON signaling is not end-to-end encrypted, and it can include IP addresses in connection candidates.

The order of a call

OrderPathWhen
1CarrierAlways first. If the friend answers there, nothing else is used.
2RSPCarrier did not reach the friend, and the friend advertises RSP/2. The caller creates the call and waits about 2 seconds for a ring, then sends a sealed wake push.
3socket.io roomThe friend does not advertise RSP/2, the node cannot create the call, or the wake is confirmed undelivered.

RSP is an extra path beside socket.io rooms and does not replace them. This is the protocol's order; each app uses the paths it has, and the web app has no socket.io room. See Which apps have it.

RSP/2

RSP/2 replaced RSP/1 on 22 November 2026. The two versions do not talk to each other:

  • A client marks its handshake with rsp=rsp/2 and signs RSP-AUTH/2 proofs. A wake push is sealed under RSP-EXPRESS-WAKE/2.
  • The node refuses RSP/1 clients at the handshake. Apps that have only RSP/1 then use their older path, push and socket.io.
  • An answered call no longer ends at 60 seconds. The 60 seconds now limit only call setup. After an answer, the reference node keeps the call's signaling for up to four hours by default.
  • Each signal carries its own expiry, at most 15 seconds after it was sent.

How a friend advertises it

The callee picks the node. It puts an rsp key in the extra field of its Carrier profile, which reaches friends and stays readable while it is offline:

{"rsp":{"protocol":"rsp/2","nodeUrl":"https://rio.beagle.chat"}}
  • protocol must be rsp/2. Apps ignore any other value, so a friend who still advertises RSP/1 is called the old way.
  • The flag holds an address only: no presence, IP address or push token. nodeUrl must be HTTPS.
  • Merge the key into the existing extra, and remove it when RSP is switched off. Decide from this flag, not from a friend's app version.

Client packages

For app developers: peer-webrtc

Apps get RSP from @decentnetwork/peer-webrtc 0.3.2, through its @decentnetwork/peer-webrtc/rsp export. That is what the web app and AgentNet use. It handles the standing listener, ringing, joining on answer, sealing the wake, and the call's signaling lifetime. Beagle apps, beagle-ui and beagle-embed should not install the two packages below.

For protocol implementers: rendezvous-protocol 0.3.0 has the wire format and validators, and rendezvous-client 0.3.1 has the low-level client. They need Node 18 or later. Install these versions together.

# Protocol implementers only. Not a dependency for Beagle apps.
mkdir rsp-demo && cd rsp-demo
npm init -y
npm install @decentnetwork/rendezvous-client@0.3.1 @decentnetwork/rendezvous-protocol@0.3.0 @decentnetwork/peer

Low-level protocol sample, not application code. Save it as call.mjs. It makes two throwaway identities in one process: one listens, and the other calls it. It runs against rio.beagle.chat as written; set RSP_NODE_URL to use a node of your own.

// Low-level RSP/2 sample for protocol implementers. Not application code.
// Two throwaway identities in one process. RSP_NODE_URL picks another node.
import { generateKeyPairSync, randomUUID } from "node:crypto";
import { RendezvousClient, SIGNAL_TTL_MS, carrierSigner, routeCall } from "@decentnetwork/rendezvous-client";
import { base58ToBytes, bytesToBase58, createCarrierRendezvousAuthProof } from "@decentnetwork/peer";

const NODE = process.env.RSP_NODE_URL ?? "https://rio.beagle.chat";

function identity() {
  const jwk = generateKeyPairSync("x25519").privateKey.export({ format: "jwk" });
  const secret = new Uint8Array(Buffer.from(jwk.d, "base64url"));
  const userid = bytesToBase58(new Uint8Array(Buffer.from(jwk.x, "base64url")));
  const signer = carrierSigner({ userid, createProof: ({ serverPublicKey, transcript }) =>
    createCarrierRendezvousAuthProof(secret, base58ToBytes(serverPublicKey), transcript) });
  return { id: { method: "carrier-x25519", id: userid }, signer };
}

const alice = identity();
const bob = identity();

// Bob listens, and rings only for a friend.
const listener = new RendezvousClient(NODE, bob.signer);
let invite;
listener.on("call:invite", async (i) => {
  if (i.caller.id !== alice.id.id) return; // not a friend: stay silent
  invite = { callId: i.callId, peer: i.caller, callExpiresAt: i.expiresAt, capability: i.joinCapability };
  await listener.ringing(invite);
});
await listener.listen();

// Alice calls. Carrier first, then RSP, then socket.io.
// Bob's Carrier profile `extra`, as Alice reads it:
const bobExtra = JSON.stringify({ rsp: { protocol: "rsp/2", nodeUrl: NODE } });
const call = await routeCall({
  tryCarrier: async () => false, // pretend Bob is not reachable over Carrier
  advertisement: bobExtra,
  signer: alice.signer,
  callId: randomUUID(),
  peer: bob.id,
  push: async () => { throw new Error("nobody rang: seal the invitation and send a wake push here"); },
  socketFallback: async () => ({ path: "socket.io" }),
});
console.log("path:", call.path);

// Bob answers. WebRTC offer and answer would follow on the same clients.
if (call.client) {
  const accepted = new Promise((resolve) => call.client.on("signal", resolve));
  await listener.join(invite);
  const now = Date.now();
  await listener.sendSignal({
    version: 1, callId: invite.callId, type: "call.accept", sequence: 1,
    timestamp: now, expiresAt: now + SIGNAL_TTL_MS, encoding: "json", payload: "{}",
  });
  console.log("received:", (await accepted).type);
  call.client.close();
}
listener.close();
node call.mjs
# path: rsp-listen
# received: call.accept
Two details to get right

routeCall gives push the join capability in clear text: seal it with sealRspWake from @decentnetwork/peer-webrtc/rsp before it goes into a push, and never log it. Each signal's expiresAt must be at most 15 seconds (SIGNAL_TTL_MS) after its timestamp; the node rejects a signal that reuses the call's 60-second deadline.

The node

https://rio.beagle.chat has run RSP/2, node version 0.3.3, since 22 November 2026. It is the only node: a test-setup node with limited capacity, not yet a general node for every Beagle user. A restart loses the calls and listeners it holds, so clients reconnect and prove their identity again.
