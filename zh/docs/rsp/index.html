RSP：通话的签名会合

通过 Carrier 联系不上好友时，用 RSP 建立通话：双方向一个小型节点证明自己的密钥，由它在两者之间传递通话信令。RSP/2 自 2026 年 11 月 22 日起在 rio.beagle.chat 上运行，部分应用已经支持。

2026 年 11 月

它是什么

RSP（Rendezvous Signaling Protocol）是一个带签名的会合点，用来呼叫 Carrier 不在线的好友。它只负责建立通话，音频和视频仍走 WebRTC。当前版本是 RSP/2。

  • 双方都证明自己的密钥。节点校验用各自身份密钥生成的证明，没有账号。
  • 一个主叫，一个被叫。加入需要一次性凭证，最先接听的设备生效。
  • 正在监听的应用无需推送即可响铃。它可以与节点保持连接，直接收到邀请。
  • 在线状态不外泄。应用只为好友响铃。对其他人来说，没有回应和离线看起来一样。
节点能看到什么

节点只在内存里保存通话状态，没有用户记录。但它能看到双方的 userid、时间，以及它转发的信令。JSON 信令不是端到端加密的，其中的连接候选可能包含 IP 地址。

通话的顺序

顺序路径何时使用
1Carrier总是最先。好友在这里接听，就不再使用其他路径。
2RSPCarrier 联系不上好友，并且好友公布了 RSP/2。主叫创建通话，等待约 2 秒响铃，之后发送加密封装的唤醒推送。
3socket.io 房间好友没有公布 RSP/2、节点无法创建通话，或确认唤醒没有送达。

RSP 是 socket.io 房间之外新增的一条路径，并不取代它。以上是协议规定的顺序；各应用使用自己具备的路径，网页应用没有 socket.io 房间。见哪些应用已支持。

RSP/2

RSP/2 于 2026 年 11 月 22 日取代 RSP/1。两个版本互不相通：

  • 客户端在握手时带上 rsp=rsp/2 标记，并签署 RSP-AUTH/2 证明。唤醒推送用 RSP-EXPRESS-WAKE/2 加密封装。
  • 节点在握手时拒绝 RSP/1 客户端。只有 RSP/1 的应用会改走原来的路径：推送加 socket.io。
  • 接听后的通话不再在 60 秒时中断。60 秒现在只限制建立通话的阶段。接听之后，参考节点默认最多保留四小时的通话信令。
  • 每条信令都有自己的过期时间，最多是发出后 15 秒。

好友如何公布支持

节点由被叫选择。被叫在自己 Carrier 资料的 extra 字段里放入 rsp 键，它会送达好友，被叫离线时仍然可读：

{"rsp":{"protocol":"rsp/2","nodeUrl":"https://rio.beagle.chat"}}
  • protocol 必须是 rsp/2。应用会忽略其他值，所以仍公布 RSP/1 的好友会按原来的方式呼叫。
  • 这个标记只有一个地址，不含在线状态、IP 地址或推送令牌。nodeUrl 必须是 HTTPS。
  • 把这个键合并进原有的 extra，关闭 RSP 时将它移除。按这个标记判断，不要按好友的应用版本判断。

客户端包

面向应用开发者：peer-webrtc

应用通过 @decentnetwork/peer-webrtc 0.3.2 的 @decentnetwork/peer-webrtc/rsp 导出获得 RSP，网页应用和 AgentNet 用的就是它。它负责常驻监听、响铃、接听时加入、唤醒的加密封装，以及通话信令的生命周期。Beagle 应用、beagle-ui 和 beagle-embed 都不应安装下面这两个包。

面向协议实现者：rendezvous-protocol 0.3.0 提供线上格式和校验，rendezvous-client 0.3.1 提供底层客户端。需要 Node 18 或更高版本。请一起安装这两个版本。

# Protocol implementers only. Not a dependency for Beagle apps.
mkdir rsp-demo && cd rsp-demo
npm init -y
npm install @decentnetwork/rendezvous-client@0.3.1 @decentnetwork/rendezvous-protocol@0.3.0 @decentnetwork/peer

这是底层协议示例，不是应用代码。保存为 call.mjs。它会在一个进程里生成两个一次性身份：一个监听，另一个呼叫它。按原样即可对 rio.beagle.chat 运行；设置 RSP_NODE_URL 可以改用你自己的节点。

// Low-level RSP/2 sample for protocol implementers. Not application code.
// Two throwaway identities in one process. RSP_NODE_URL picks another node.
import { generateKeyPairSync, randomUUID } from "node:crypto";
import { RendezvousClient, SIGNAL_TTL_MS, carrierSigner, routeCall } from "@decentnetwork/rendezvous-client";
import { base58ToBytes, bytesToBase58, createCarrierRendezvousAuthProof } from "@decentnetwork/peer";

const NODE = process.env.RSP_NODE_URL ?? "https://rio.beagle.chat";

function identity() {
  const jwk = generateKeyPairSync("x25519").privateKey.export({ format: "jwk" });
  const secret = new Uint8Array(Buffer.from(jwk.d, "base64url"));
  const userid = bytesToBase58(new Uint8Array(Buffer.from(jwk.x, "base64url")));
  const signer = carrierSigner({ userid, createProof: ({ serverPublicKey, transcript }) =>
    createCarrierRendezvousAuthProof(secret, base58ToBytes(serverPublicKey), transcript) });
  return { id: { method: "carrier-x25519", id: userid }, signer };
}

const alice = identity();
const bob = identity();

// Bob listens, and rings only for a friend.
const listener = new RendezvousClient(NODE, bob.signer);
let invite;
listener.on("call:invite", async (i) => {
  if (i.caller.id !== alice.id.id) return; // not a friend: stay silent
  invite = { callId: i.callId, peer: i.caller, callExpiresAt: i.expiresAt, capability: i.joinCapability };
  await listener.ringing(invite);
});
await listener.listen();

// Alice calls. Carrier first, then RSP, then socket.io.
// Bob's Carrier profile `extra`, as Alice reads it:
const bobExtra = JSON.stringify({ rsp: { protocol: "rsp/2", nodeUrl: NODE } });
const call = await routeCall({
  tryCarrier: async () => false, // pretend Bob is not reachable over Carrier
  advertisement: bobExtra,
  signer: alice.signer,
  callId: randomUUID(),
  peer: bob.id,
  push: async () => { throw new Error("nobody rang: seal the invitation and send a wake push here"); },
  socketFallback: async () => ({ path: "socket.io" }),
});
console.log("path:", call.path);

// Bob answers. WebRTC offer and answer would follow on the same clients.
if (call.client) {
  const accepted = new Promise((resolve) => call.client.on("signal", resolve));
  await listener.join(invite);
  const now = Date.now();
  await listener.sendSignal({
    version: 1, callId: invite.callId, type: "call.accept", sequence: 1,
    timestamp: now, expiresAt: now + SIGNAL_TTL_MS, encoding: "json", payload: "{}",
  });
  console.log("received:", (await accepted).type);
  call.client.close();
}
listener.close();
node call.mjs
# path: rsp-listen
# received: call.accept
两个需要注意的细节

routeCall 交给 push 的加入凭证是明文：放进推送之前，请用 @decentnetwork/peer-webrtc/rsp 的 sealRspWake 加密封装，并且绝不要写进日志。每条信令的 expiresAt 最多比它的 timestamp 晚 15 秒（SIGNAL_TTL_MS）；沿用通话 60 秒截止时间的信令会被节点拒绝。

节点

https://rio.beagle.chat 自 2026 年 11 月 22 日起运行 RSP/2，节点版本 0.3.3。它是唯一的节点：一个容量有限的测试环境节点，还不是面向所有 Beagle 用户的通用节点。重启会丢失它持有的通话和监听，所以客户端需要重新连接并再次证明身份。

应用RSP

AndroidRSP/2，Google Play 1.4.72 起。1.4.72 收到 RSP 来电时只在状态栏显示图标，不响铃；issue 14 说明已在 1.4.74 修复，在真机上确认之前保持开启。1.4.68 只有 RSP/1，会走推送加 socket.io。
iOSRSP/2 在 1.8.47 中，正在 TestFlight 测试。App Store 上的 1.8.45 和已提交 App Store 审核的 1.8.46 只有 RSP/1，会走推送加 socket.io。
