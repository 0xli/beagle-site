RSP：通话的签名会合

通过 Carrier 联系不上好友时，用 RSP 建立通话：双方向一个小型节点证明自己的密钥，由它在两者之间传递通话信令。这是新功能，运行在测试环境的节点上，也还没有进入所有应用。

2026 年 11 月

它是什么

RSP（Rendezvous Signaling Protocol，rsp/1）是一个带签名的会合点，用来呼叫 Carrier 不在线的好友。它只负责建立通话，音频和视频仍走 WebRTC。

  • 双方都证明自己的密钥。节点校验用各自身份密钥生成的证明，没有账号。
  • 一个主叫，一个被叫。加入需要一次性凭证，最先接听的设备生效。
  • 正在监听的应用无需推送即可响铃。它可以与节点保持连接，直接收到邀请。
  • 在线状态不外泄。应用只为好友响铃。对其他人来说，没有回应和离线看起来一样。
节点能看到什么

节点只在内存里保存通话状态，没有用户记录。但它能看到双方的 userid、时间，以及它转发的信令。JSON 信令不是端到端加密的，其中的连接候选可能包含 IP 地址。

通话的顺序

顺序路径何时使用
1Carrier总是最先。好友在这里接听，就不再使用其他路径。
2RSPCarrier 联系不上好友，并且好友公布了 RSP。主叫创建通话，等待约 2 秒响铃，之后发送加密封装的唤醒推送。
3socket.io 房间好友没有公布 RSP、节点无法创建通话，或确认唤醒没有送达。

RSP 是 socket.io 房间之外新增的一条路径，并不取代它。以上是协议规定的顺序，各应用目前的支持情况见哪些应用已支持。

好友如何公布支持

节点由被叫选择。被叫在自己 Carrier 资料的 extra 字段里放入 rsp 键，它会送达好友，被叫离线时仍然可读：

{"rsp":{"protocol":"rsp/1","nodeUrl":"https://rio.beagle.chat"}}
  • 这个标记只有一个地址，不含在线状态、IP 地址或推送令牌。nodeUrl 必须是 HTTPS。
  • 把这个键合并进原有的 extra，关闭 RSP 时将它移除。
  • 按这个标记判断，不要按好友的应用版本判断。

底层协议客户端

不是给应用开发者安装的包

这两个包面向要在自己的技术栈里实现 RSP 的人。Beagle 应用、beagle-ui 和 beagle-embed 都不应安装或依赖它们：它们只是协议组件，不含好友策略、加密封装的推送和媒体。计划在 @decentnetwork/peer-webrtc 中提供共享的 RSP 层，但它尚未开发完成，也没有发布，所以目前还没有受支持的包可以给应用加入 RSP。

面向协议实现者：npm 上有两个包，版本 0.2.0，需要 Node 18 或更高版本：rendezvous-protocol 提供线上格式和校验，rendezvous-client 提供客户端。两者请安装同一版本。

# Protocol implementers only. Not a dependency for Beagle apps.
mkdir rsp-demo && cd rsp-demo
npm init -y
npm install @decentnetwork/rendezvous-client@0.2.0 @decentnetwork/rendezvous-protocol@0.2.0 @decentnetwork/peer

这是底层协议示例，不是应用代码。保存为 call.mjs。它会在一个进程里生成两个一次性身份：一个监听，另一个经测试节点呼叫它。

// Low-level RSP/1 sample for protocol implementers. Not application code.
// Two throwaway identities in one process, over the test node.
import { generateKeyPairSync, randomUUID } from "node:crypto";
import { RendezvousClient, carrierSigner, routeCall } from "@decentnetwork/rendezvous-client";
import { base58ToBytes, bytesToBase58, createCarrierRendezvousAuthProof } from "@decentnetwork/peer";

const NODE = "https://rio.beagle.chat";

function identity() {
  const jwk = generateKeyPairSync("x25519").privateKey.export({ format: "jwk" });
  const secret = new Uint8Array(Buffer.from(jwk.d, "base64url"));
  const userid = bytesToBase58(new Uint8Array(Buffer.from(jwk.x, "base64url")));
  const signer = carrierSigner({ userid, createProof: ({ serverPublicKey, transcript }) =>
    createCarrierRendezvousAuthProof(secret, base58ToBytes(serverPublicKey), transcript) });
  return { id: { method: "carrier-x25519", id: userid }, signer };
}

// A friend's `extra` is not the shape routeCall takes: convert it.
function advertisement(extra) {
  const rsp = JSON.parse(extra || "{}").rsp;
  if (rsp?.protocol === "rsp/1" && rsp.nodeUrl === NODE) return { rsp: true, nodeUrl: NODE };
}

const alice = identity();
const bob = identity();

// Bob listens, and rings only for a friend.
const listener = new RendezvousClient(NODE, bob.signer);
let invite;
listener.on("call:invite", async (i) => {
  if (i.caller.id !== alice.id.id) return; // not a friend: stay silent
  invite = { callId: i.callId, peer: i.caller, callExpiresAt: i.expiresAt, capability: i.joinCapability };
  await listener.ringing(invite);
});
await listener.listen();

// Alice calls. Carrier first, then RSP, then socket.io.
const bobExtra = JSON.stringify({ rsp: { protocol: "rsp/1", nodeUrl: NODE } });
const call = await routeCall({
  tryCarrier: async () => false, // pretend Bob is not reachable over Carrier
  advertisement: advertisement(bobExtra),
  signer: alice.signer,
  callId: randomUUID(),
  peer: bob.id,
  push: async () => { throw new Error("nobody rang: send a sealed wake push here"); },
  socketFallback: async () => ({ path: "socket.io" }),
});
console.log("path:", call.path);

// Bob answers. WebRTC offer and answer would follow on the same clients.
if (call.client) {
  const accepted = new Promise((resolve) => call.client.on("signal", resolve));
  await listener.join(invite);
  await listener.sendSignal({
    version: 1, callId: invite.callId, type: "call.accept", sequence: 1,
    timestamp: Date.now(), expiresAt: invite.callExpiresAt, encoding: "json", payload: "{}",
  });
  console.log("received:", (await accepted).type);
  call.client.close();
}
listener.close();
node call.mjs
# path: rsp-listen
# received: call.accept
两个需要注意的细节

routeCall 接受的是 { rsp: true, nodeUrl }。如果把好友的 extra 原样传入，它会不报错地改走 socket.io。另外，它交给 push 的加入凭证是明文：放进推送之前要先为被叫加密封装，并且绝不要写进日志。

节点：测试环境

https://rio.beagle.chat 已经上线，但它服务于测试环境。它还不是面向所有 Beagle 用户的通用节点。它是一个通过 Socket.IO 访问的 RSP/1 单节点。重启会丢失它持有的通话和监听，所以客户端需要重新连接并再次证明身份。

一条通话记录只保留 60 秒

无论是否接听，节点都会在通话创建 60 秒后结束这条记录。目前的网页、iOS 和 Android 应用也会在此时挂断 RSP 通话。这是已知缺陷：暂时不要用 RSP 进行超过一分钟的通话。
