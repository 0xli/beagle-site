beagle-service：Beagle 登录的服务端

一个 npm 包，用于访客以 Beagle 身份登录的网站的服务端：登录与会话、你自己的用户记录，以及网站自己在网络上的身份。本页对应 0.3.0 版。

2026 年 11 月

它是什么

@decentnetwork/beagle-service 是浏览器端 @decentnetwork/beagle-connect 调用所对接的服务端。访客的身份是在自己设备上生成的一对密钥，userid 就是它的公钥。你的网站通过签名知道访客是谁，保存自己的访客记录，并可以用网站自己的身份给他们发消息。中间没有账号服务器。

如果你本来要自己写给你的应用接入 Beagle 登录里的服务端验签，再加上 nonce 存储、会话和用户表，就用它。本页对应 0.3.0 版，即 npm 上的 latest。需要 Node 20 或更高版本，import 和 require 都能用。

部分作用
auth服务端登录：一次性 nonce、精确的来源（origin）检查、验签、有过期时间的会话和退出登录、频率限制。提供 node:http、Express 和 Next.js 的路由。
users每个 userid 一条记录：visitor、registered 或 blocked。注册字段由你决定，可以屏蔽和解除屏蔽。
agent网站自己在网络上的身份，运行在你的进程里：按策略接受好友请求，收发消息。

快速开始

mkdir my-site && cd my-site
npm init -y
npm install @decentnetwork/beagle-service

最小的服务端：/api/auth 下的登录路由，加上一个只回应已登录者的自有页面。保存为 server.mjs。

import http from "node:http";
import { createBeagleService } from "@decentnetwork/beagle-service";

const svc = await createBeagleService({
  origins: ["http://localhost:3000"],   // exact: scheme, host and port
  dataDir: "./data",
});
const auth = svc.nodeHandler({ prefix: "/api/auth" });

http.createServer(async (req, res) => {
  if (req.url.startsWith("/api/auth/")) return auth(req, res);
  const who = await svc.auth.authenticate(req);   // never throws; decide on who.ok
  res.writeHead(who.ok ? 200 : who.status, { "content-type": "application/json" });
  res.end(JSON.stringify(who.ok ? { hello: who.user.userid } : { error: who.error }));
}).listen(3000);

怎么确认它在工作。 nonce 路由有回应，你的页面拒绝陌生人，用一次性密钥登录的脚本拿到会话，并出现在用户列表里。在本机测试时，服务端还会打印一行提示，说无法对来自本机的请求限频；本地测试时这是正常的。

node server.mjs &
curl http://localhost:3000/api/auth/nonce     # {"ok":true,"nonce":"…","expiresIn":120}
curl http://localhost:3000/                   # {"error":"not-signed-in"}

# sign in with a throwaway key, the way a script or a test does
cp node_modules/@decentnetwork/beagle-service/examples/sign-in-from-script.mjs .
node sign-in-from-script.mjs http://localhost:3000   # signed in as <userid>
npx beagle-service users list

登录按钮。 包里自带一个单文件网站和页面 examples/minimal-site：两个按钮，一个给装在访客电脑上的 Beagle，一个给浏览器里的 Beagle（app.beagle.chat）。两者都只是访客身份所在的地方之一。页面使用 beagle-connect 的 signIn、readLaunch 和 addFriend。启动前先停掉第一个服务，两者都用 3000 端口。

npm install @decentnetwork/beagle-connect esbuild
cp -R node_modules/@decentnetwork/beagle-service/examples/minimal-site .
node minimal-site/server.mjs          # then open http://localhost:3000

三个部分

auth。 svc.nodeHandler()（或 expressHandler()、route(name)、nextApiHandler()、fetchHandler()）提供 nonce、sign-in、launch、me、logout 和 register。在你自己的路由里，像上面的 server.mjs 那样调用 await svc.auth.authenticate(req)。它从不抛异常，只按 who.ok 判断，别的都不要看。

users。 记录存在 <dataDir>/users.json，除非你传入自己的 store。register: { required: ["email"] } 表示访客填齐这些字段后成为 registered。运维命令可以在服务运行时使用，屏蔽立即生效：登录返回 403，该 userid 的会话全部失效。

npx beagle-service users list
npx beagle-service users show    <userid>
npx beagle-service users block   <userid> spam
npx beagle-service users unblock <userid>

agent。 在选项里加上 agent，网站就有了自己的身份，密钥在 <dataDir>/agent/peer.save。大家像添加任何联系人一样添加它的地址。好友请求被接受之前，双向都不投递任何内容。发好友请求需要访客的地址（address），只有 userid 不够。

import { createBeagleService } from "@decentnetwork/beagle-service";

const svc = await createBeagleService({
  origins: ["http://localhost:3000"],
  dataDir: "./data",
  agent: { nickname: "My Site", accept: "signed-in", befriendOn: "register" },
});

console.log("add this address in Beagle:", svc.agent.address);
svc.agent.onMessage(({ user, text, reply }) =>
  reply(user ? `You said: ${text}` : "Sign in on the site first."));

部署

import { createBeagleService } from "@decentnetwork/beagle-service";

const svc = await createBeagleService({
  origins: ["https://your.app"],            // scheme, host and port: what the address bar shows
  rateLimit: { trustProxy: ["loopback"] },  // nginx or Caddy on the same machine
  dataDir: "./data",                        // keep it: users, sessions, the agent's key
});
console.log(svc.auth.origins());
await svc.close();
  • `origins` 写浏览器地址栏显示的准确内容：协议、主机和端口。只有列出 http://localhost:3000 时它才算数。裸主机名、路径或 * 会让服务在启动时就停下。
  • 在反向代理后面，要设置 `trustProxy`。 登录按访客限频（默认每分钟 30 次）。同一台机器上有 nginx 或 Caddy 而什么都不设时，登录完全不限频；代理在另一台机器上时，所有访客共用代理的地址。请写明代理：["loopback"] 或它的地址。
  • 保留数据目录，不放进 git，并做好备份。里面有用户、用过的 nonce 和已注销的会话、会话密钥，以及 agent 的密钥。丢了 agent/peer.save，网站的身份就没了。
  • Node 20 或更高版本。 多台服务器共用一套用户时需要同一个 sessionSecret。这一点以及 Next.js 的用法见 README。

常见错误

  • 403 `origin-not-allowed`。 页面的来源不在列表里，或写得不完全一致。http://127.0.0.1:3000 不等于 http://localhost:3000，https 也不等于 http。
  • 脚本登录时没带 `Origin`。 浏览器会自己带上这个请求头；脚本必须自己发送，并对同一个来源签名。不带就返回 403 origin-not-allowed。服务端从不从请求体里取来源。
  • 把读取会话失败当成公开访问。 没有会话、用户被屏蔽、存储读不出来，authenticate() 都返回 ok: false 和状态码。把它包在 try { … } catch { /* 公开 */ } 里，或者忘了 await，私密页面就会给任何人看到。
